# Publish and present this project

Suggested repository name: **food-bank-disaster-analysis**.

Suggested description: **Python + SQL case study of food-bank order activity during disasters, with audited metrics, robust uncertainty, and an offline interactive report.**

## GitHub distribution

1. Create a repository in the owner's GitHub account and upload the contents of this release directory, keeping `README.md` at the repository root. Upload the source files rather than only the ZIP so reviewers can browse the code, data, and findings.
2. Preserve the contribution and source statements. Do not add a blanket license for partner materials without an applicable grant; publication permission is already recorded.
3. Pin the repository on the GitHub profile and use the project card in [RECRUITING.md](RECRUITING.md). Suggested topics: `python`, `sql`, `data-analysis`, `decision-science`, `disaster-response`.
4. Direct a reviewer to the README and findings first. GitHub displays the HTML file as source; download and open `reports/report.html` for the interactive version. Hosting is optional, and no deployed URL is claimed.

No account name, remote URL, publication, or hosting status is assumed here.

## Interview preparation

Read the report, then explain the question, the qualifying-order definition, the estimate and interval, and the decision implication in one minute. Follow the technical walkthrough and practice questions in [RECRUITING.md](RECRUITING.md). Be ready to distinguish original R authorship, collaborative source materials, and the Codex-assisted Python rebuild.

The substantive story is how data validation changed the metric and how uncertain evidence constrained the operational recommendation. The value of this project does not depend on obtaining a statistically significant increase.
